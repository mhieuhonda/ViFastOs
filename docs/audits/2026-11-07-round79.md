# Audit toàn cảnh — 2026-11-07 (subagent DeepSeek V4.1 Flash)

Audit read-only do subagent thực hiện đầu vòng 79, theo yêu cầu "mỗi vòng có
một AI khác đánh giá toàn cảnh". Báo cáo giữ nguyên nội dung; các mục đã sửa
được ghi chú ngay dưới tiêu đề.

> Trạng thái sau vòng 80:
> - P0-1 (`FrameWrite` không validate con trỏ): **đã sửa** — kernel kiểm tra
>   `validate_user_range` với `USER_COPY_MAX`; ba helper `page_in_range`/
>   `user_range` dùng `checked_add`; có test host.
> - P0-2 (underflow `ip_total - ihl`): **đã sửa** — chặn `ip_total < ihl + 20`
>   và kẹp độ dài copy theo buffer.
> - P1-2 (RX descriptor treo trùng): **đã sửa** — chỉ treo một chain tại một
>   thời điểm (`RX_OUTSTANDING`), `net_rx_refill` thành một lần đăng.
> - P1-3 (static budget quá rộng): **chưa sửa** — ưu tiên vòng sau.
> - P1-4 (check-docs phụ thuộc mtime): **chưa sửa**.
> - P1-6 (`pick_on` không lọc TCB không chạy được): **chưa xác nhận**.

## Tổng quan

- Layering is sane: `vifast-kernel` is 5.9k lines of `#![forbid(unsafe_code)]`,
  no unwrap/expect outside tests, fixed-capacity object model; `lib.rs` is
  ~11.7k lines with ~5.8k of `#[cfg(test)]`, and complexity concentrates in
  object/cap lifecycle (retype/revoke/destroy ≈ 1.4k lines) and MMU
  bookkeeping (map/remap/unmap/walk ≈ 1.1k lines).
- The syscall surface is small and deliberately capability-checked; dispatch is
  a single match over `SyscallId` with per-arm type+rights checks.
- The weakest seam is the **user↔kernel copy boundary**: the three platforms
  implement `read_user`/`write_user` as "pointer inside a hard-coded VA window"
  plus raw `copy_nonoverlapping`, and `FrameWrite` reached them with no
  validation at all.
- Second weak seam: the **VirtIO RX path** — fixed static queues, descriptor
  bookkeeping by convention, parsers that trust on-wire length fields.
- Third: memory accounting has failure paths that silently leak, and the
  "static budget" guard is 155 KB looser than the object it guards.
- Test harness is unusually strong (504 negative cases, mtime-keyed doc gate,
  artifacts on timeout) but the two heaviest fuzzers are `#[ignore]`d, and the
  docs-harness contract was loosened in code without updating the text.

## P0

### P0-1. `FrameWrite` never validates the user pointer (all 3 arches)
- `crates/vifast-kernel/src/lib.rs:5727` returned `UserAction::FrameWrite`
  straight from syscall args; every other pointer-taking syscall calls
  `validate_user_range`.
- `crates/vifast-runtime/src/lib.rs:1045` then calls `A::read_user`, which is
  only a window test (`platform-aarch64:477`, `riscv64:374`, `x86_64:717`)
  followed by `copy_nonoverlapping`.
- Failure: `frame_write(slot, 0, CODE_VA + 0x1f000, 8)` — inside the window but
  past the mapped image — faults at EL1 and prints `KERNEL EXCEPTION`.
- Worse variant: `ptr = 0xFFFF_FFFF_FFFF_FFF0, len = 16` wraps the window test.
- Fix applied: validate in the syscall arm with `USER_COPY_MAX`; use
  `checked_add` in the three helpers.

### P0-2. VirtIO TCP RX `ip_total - ihl` underflow
- `crates/vifast-virtio/src/lib.rs:2317`: `let tcp_total = ip_total - ihl;`
  guarded only by `ihl >= 20` and `14 + ip_total <= buf.len()`; a frame with
  IHL=60 and total length 20 underflows, so `data_len` becomes huge and the
  driver copies stale RX-buffer bytes and echoes them back to the peer.
- Fix applied: require `ip_total >= ihl + 20`, clamp copy to the buffer.

## P1

### P1-1. Untyped bytes leak when allocation fails after the take
- `lib.rs:1698` takes bytes then `alloc_owned(...).ok_or(OutOfMemory)?`; if the
  object table is full the bytes are never reclaimed. Same at `1805`/`1824`.

### P1-2. RX descriptors posted multiple times (same chain queued 8×)
- `net_rx_post` always queues chain 0 and `net_rx_refill` looped up to 8 times,
  so 8 identical chains were in flight; the device can write two packets to the
  same buffer while `net_rx_poll_bounded` advances `RX_SEEN` by one.
- Fix applied: one outstanding chain at a time (`RX_OUTSTANDING`).

### P1-3. The static-storage guard cannot protect the AArch64 8-byte gap
- `KERNEL_STATIC_BUDGET = 716_800` vs actual `Kernel = 561_768`: the check
  allows +155 KB while the hazard is a neighbour collision at the real end of
  the static. No linker `ASSERT`, no `nm`-based distance check.

### P1-4. `check-docs.py` is mtime-coupled
- `gen-docs.py:155` fails when `target/qemu-status-standard.json` is older than
  `target/vifast-build.log`; any build after the last QEMU run turns the gate
  red for reasons unrelated to docs. Compare a content hash instead.

### P1-5. `FORBIDDEN "STALL"` collides with `USER CODE CAP INSTALL FAILED`
- `harness_spec.py:77` forbids the substring `STALL`, which matches the
  kernel's own `INSTALL` diagnostic.

### P1-6. `pick_on` does not filter non-runnable TCBs (needs confirmation)
- `lib.rs:4431` picks by affinity/priority and sets `state = Running` without a
  `state == Ready` check; VSpace destroy sets TCBs to `Faulted` without
  removing them from the runqueue.

## P2

- Documented fault contract is stricter than the enforced one
  (`harness_spec.py:225` vs `accept()` at `362`).
- The two heaviest fuzzers are `#[ignore]`d (`lib.rs:6592`, `10643`) and never
  run in any gate.
- `check_invariants` is test-only (`lib.rs:2555`), 20 hits all inside tests.
- 53 sites do `slot_arg(..).unwrap_or(0)`, turning `InvalidArg` into slot 0.
- Stale comment on `net_send_udp` ("payload tối đa 26 byte") vs a 2006-byte
  bound.
- `net_recv_udp` is unvalidated dead code (`lib.rs:432`).
- `MAX_OBJECTS = 147` is hand-tuned; derive it from TCB counts with a const
  assert so it cannot drift from the `.bss` gap.

## Đề xuất 3 việc tiếp theo (từ audit)

1. Close the user-copy boundary (S, ~2 h) — done in vòng 80.
2. Harden the VirtIO RX parsers (M, ~4 h) — partly done; next: per-descriptor
   buffers and a host fuzz test over random frames.
3. Make memory accounting failure-safe and the AArch64 layout self-checking
   (M, ~5 h) — reclaim on failed retype, `nm`-based `.bss`-to-`BKL` gate.
